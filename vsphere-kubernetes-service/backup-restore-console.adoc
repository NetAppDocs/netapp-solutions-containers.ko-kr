= NetApp Console을 사용하여 vSphere Kubernetes Service 클러스터의 컨테이너 애플리케이션을 백업 및 복구합니다.
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
NetApp Console을 사용하여 vSphere Kubernetes Service(VKS) 클러스터에서 컨테이너 애플리케이션을 백업하고 복구합니다. 이 절차에서는 NetApp Console의 NetApp Backup and Recovery 서비스를 통해 백업 및 복구 작업을 생성하고 관리하는 방법을 다룹니다.

이 예시들은 다음 두 가지 백업 및 복원 시나리오를 다룹니다.

. ONTAP S3 오브젝트 스토리지를 백업 대상으로 사용하여 백업 및 복원(디스크-to-오브젝트 워크플로)을 수행합니다.
. ONTAP를 백업 대상으로 사용하여 백업 및 복원(디스크 간 워크플로)을 수행합니다.



NOTE: VKS 워크로드에서는 현재 3-2-1 팬아웃 정책(디스크 간 및 디스크-오브젝트 워크플로우)을 사용한 백업 및 복원이 지원되지 않습니다.

NetApp Console은 온프레미스 및 클라우드 환경 전반에 걸쳐 스토리지 및 데이터 서비스를 중앙에서 관리할 수 있도록 지원합니다. 통합 제어, 간편한 운영, 안전한 관리를 제공합니다. 여러 데이터 서비스 및 관리 기능은 link:https://console.netapp.com["console.netapp.com"^]의 사용자 인터페이스에서 액세스할 수 있습니다. NetApp Console에 대한 자세한 내용은 link:https://docs.netapp.com/us-en/console-family/["NetApp Console 설명서"]을 참조하십시오.

이 섹션에서는 Kubernetes 워크로드, 특히 vSphere Kubernetes Service 클러스터의 컨테이너 애플리케이션을 위한 NetApp Backup and Recovery 데이터 서비스에 초점을 맞춥니다. NetApp Backup and Recovery 서비스를 사용하면 단일 인터페이스를 통해 Kubernetes 애플리케이션을 검색, 관리, 생성하고 보호 정책을 연결할 수 있습니다. 전체 가이드는 link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["NetApp Backup and Recovery 설명서"]을 참조하십시오.


NOTE: 이 절차는 VKS 클러스터가 실행 중인 환경에 콘솔 에이전트가 이미 배포되었다고 가정합니다. 백업 및 복원 작업을 진행하기 전에 에이전트가 NetApp Console에 제대로 등록되어 표시되는지 확인하십시오.



[[backup-and-recovery-workflow]]
== 백업 및 복구 워크플로

. *콘솔 에이전트가 있는지 확인하십시오*
+
VKS 클러스터가 실행 중인 환경에 Console 에이전트가 배포되어 있는지 확인하십시오. Console 에이전트 설치에 대한 자세한 내용은 link:https://docs.netapp.com/us-en/console-setup-admin/task-install-agent-on-prem-ova.html#install-a-console-agent-in-your-vcenter-environment["NetApp Console Setup 설명서"]을 참조하십시오.

+
.예제 표시
[%collapsible]
====
NetApp Console에서 스크린샷에 표시된 대로 *Deploy Agent*를 클릭하고 VKS 클러스터가 실행 중인 환경에 에이전트를 배포합니다.

이 예에서는 *온프레미스 > OVA 사용*을 선택하고 OVA URL을 복사한 다음 vCenter에서 해당 URL을 사용하여 Console 에이전트를 배포합니다.

URL에 에이전트의 IP 주소를 사용하여 등록하십시오. 자세한 지침은 link:https://docs.netapp.com/us-en/console-setup-admin/task-install-agent-on-prem-ova.html["문서"]을 참조하십시오. 에이전트가 등록되면 아래 스크린샷과 같이 NetApp Console에서 확인할 수 있습니다.

image::vks-console-br-001.png[콘솔 에이전트 설치]

image::vks-console-br-002.png[에이전트 설치 프로그램 URL 사용]

====
. *ONTAP 클러스터를 NetApp Console에 추가하고 Backup and Recovery를 활성화합니다.*
+
워크로드를 보호하려면 먼저 기본 ONTAP 클러스터를 NetApp Console에 추가하고 해당 클러스터에서 Backup and Recovery 서비스를 활성화해야 합니다. 지침은 link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-start-setup.html["NetApp Backup and Recovery 설정"]을 참조하십시오.

. *NetApp Console에서 vSphere Kubernetes 클러스터를 검색합니다*
+
.예제 표시
[%collapsible]
====
이 단계를 수행하려면 vSphere Kubernetes 클러스터가 실행 중이어야 하며 동일한 환경에 Console 에이전트가 배포되어 있어야 합니다.

다음 단계를 수행하여 NetApp Console에서 vSphere Kubernetes 클러스터를 검색하십시오.

.. NetApp Console에서 *인벤토리 > Kubernetes*를 선택하고 vSphere Kubernetes 클러스터의 세부 정보를 입력하십시오.
.. vSphere Kubernetes 클러스터가 위치한 환경과 동일한 환경에 배포된 에이전트를 선택하십시오.
.. 제공된 명령어를 복사하여 Trident Protect를 설치하고 vSphere Kubernetes 클러스터에 연결된 컴퓨터에서 실행하십시오.
.. Trident Protect가 성공적으로 설치되면 *검색*을 클릭하십시오. NetApp Console은 에이전트를 통해 vSphere Kubernetes 클러스터와 모든 리소스를 검색하고 사용자 인터페이스에 표시합니다.


image::vks-console-br-007.png[vSphere Kubernetes 클러스터 검색]

image::vks-console-br-008.png[Trident Protect를 설치한 다음 Discover를 클릭하십시오.]

image::vks-console-br-009.png[Trident Protect 설치가 완료되었습니다.]

image::vks-console-br-010.png[NetApp Console에서 검색된 vSphere Kubernetes 클러스터]

====
. *ONTAP S3를 백업 대상으로 설정*
+
이 예제에서는 ONTAP S3 오브젝트 스토리지를 백업 대상으로 사용합니다. AWS S3, Azure Blob, Google Cloud Storage 또는 StorageGRID를 백업 대상으로 사용할 수도 있습니다.

+
자세한 내용은 link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-start-setup.html#prepare-the-backup-destination["NetApp Console 설명서"]을 참조하십시오.

+
ONTAP S3를 NetApp Console에서 백업 대상으로 추가하려면 ONTAP 클러스터에서 다음 정보가 필요합니다.

+
[listing]
----
S3 Endpoint:
Access Key:
Secret Key:
Bucket Name:
----
+
이러한 값을 얻으려면 System Manager를 사용하여 ONTAP 클러스터에서 다음 단계를 수행하십시오.

+
.. ONTAP 클러스터에 S3 지원 SVM을 생성하여 백업 데이터를 저장합니다. 이 SVM의 S3 엔드포인트 URL을 기록해 두십시오.
.. SVM의 S3 설정에서 사용자를 생성하고 필요한 접근 권한을 할당합니다. 이 사용자의 접근 키와 비밀 키를 기록해 둡니다.
+

NOTE: Trident Protect를 사용하려면 S3 사용자에게 최소한  `PutObject`,  `GetObject`,  `ListBucket` 및  `DeleteObject` 권한이 있어야 합니다. 이러한 권한이 없으면 AppVault 백업 및 복원 작업이 액세스 거부 오류와 함께 실패합니다. 자세한 내용은 link:https://docs.netapp.com/us-en/trident/trident-protect/trident-protect-appvault-custom-resources.html#s3-compatible-storage-iam-permissions["Trident Protect AppVault 문서"]을 참조하십시오.

+

. *NetApp Console에서 컨테이너 워크로드용 애플리케이션을 생성하고 백업을 사용하여 보호합니다.*
+

NOTE: Kubernetes 애플리케이션을 생성하고 보호하려면 백업 및 복구 슈퍼 관리자 또는 백업 및 복구 백업 관리자 역할이 필요합니다. Kubernetes 애플리케이션을 복원하려면 백업 및 복구 슈퍼 관리자 또는 백업 및 복구 복원 관리자 역할이 필요합니다.

+

image::vks-console-br-011.png[컨테이너 애플리케이션용 애플리케이션 생성]

image::vks-console-br-012.png[애플리케이션 세부 정보를 제공하고 애플리케이션 기준을 정의하십시오.]

다음으로 애플리케이션에 대한 보호 설정을 제공해야 합니다. 새 보호 정책을 만들거나 기존 정책을 사용할 수 있습니다. 이 예에서는 애플리케이션에 대한 새 보호 정책을 만들고 연결합니다. *정책*을 확장하고 *새 정책 만들기*를 클릭합니다.

image::vks-console-br-013.png[새 보호 정책 생성]

.예시 보기: 디스크-오브젝트 스토리지 아키텍처를 사용하여 보호 정책 생성
[%collapsible]
====
정책 이름을 지정하고 백업 아키텍처를 선택합니다. 이 예에서는 디스크-오브젝트 스토리지를 선택했습니다. 기본 스토리지에서 스냅샷을 생성하는 빈도를 제어하는 로컬 스냅샷 일정을 정의합니다. 그런 다음 스냅샷에 사용되는 Kubernetes 애플리케이션 메타데이터의 오브젝트 스토리지 대상을 선택합니다.

다음으로, 오브젝트 스토리지 백업 설정을 별도로 구성합니다. 백업 대상(이 예에서는 ONTAP S3)을 선택하고, 스냅샷 데이터가 오브젝트 스토리지로 복사되는 시점을 제어하는 전송 일정을 설정하고, 보존 복사본 수를 지정합니다. 전송 일정은 스냅샷 일정과 별개이므로 리소스는 각 스냅샷이 생성될 때 즉시 복사되는 것이 아니라 전송 일정에 따라 오브젝트 스토리지로 복사됩니다. 필요한 경우 최대 재시도 횟수와 재시도 간격을 수정할 수도 있습니다. *생성*을 클릭하여 진행합니다. 애플리케이션이 검색되고 보호 정책이 연결됩니다.

image::vks-console-br-017.png[백업을 위한 오브젝트 저장소 설정]

.예시 보기: 디스크 대 디스크 아키텍처를 사용하여 보호 정책 생성
[%collapsible]
====

NOTE: 디스크 대 디스크 아키텍처를 선택하려면 2차 스토리지 대상이 클러스터 피어링 및 SVM 피어링으로 구성되어 있고 필요한 자격 증명과 권한이 있는지 확인하십시오.

정책 이름을 지정하고 백업 아키텍처를 선택합니다. 이 예에서는 디스크 대 디스크 백업이 선택되었습니다. 기본 스토리지에서 스냅샷을 생성하는 빈도를 제어하는 로컬 스냅샷 일정을 정의합니다. 그런 다음 스냅샷의 Kubernetes 애플리케이션 메타데이터에 사용할 오브젝트 스토리지 위치를 선택합니다.

2차 스토리지 백업 설정을 별도로 구성합니다. 드롭다운 목록에서 백업 대상, 백업용으로 구성된 ONTAP 클러스터 및 SVM, 백업 볼륨이 생성될 애그리게이트를 선택합니다. 스냅샷 데이터가 2차 스토리지에 복사되는 시기를 제어하는 전송 일정을 설정하고 보존 복사본 수를 지정합니다. 전송 일정은 스냅샷 일정과 독립적이므로 리소스는 각 스냅샷이 생성될 때 즉시 복사되는 것이 아니라 전송 일정에 따라 보조 대상으로 복사됩니다. 또한 SnapMirror 복사본의 애플리케이션 메타데이터가 저장될 오브젝트 스토리지 대상을 구성합니다.

필요에 따라 최대 재시도 횟수와 재시도 간격을 수정할 수도 있습니다. *생성*을 클릭하여 진행합니다. 애플리케이션이 검색되고 해당 애플리케이션에 보호 정책이 연결됩니다.

image::vks-console-br-027.png[보호 정책 이름을 제공하고 백업 아키텍처를 선택하십시오.]

image::vks-console-br-028.png[로컬 스냅샷 설정]

image::vks-console-br-029.png[디스크 간 디스크 백업을 위한 2차 스토리지 설정]

. *백업에서 애플리케이션을 복원합니다*
+

NOTE: Kubernetes 애플리케이션을 복원하려면 Backup and Recovery 슈퍼 관리자 또는 Backup and Recovery 복원 관리자 역할이 필요합니다.

+
** 애플리케이션을 복원하려면 로컬 스냅샷, 오브젝트 스토리지 백업 또는 2차 대상의 백업과 같은 사용 가능한 복원 지점을 선택할 수 있습니다.
** 애플리케이션을 원래 네임스페이스 또는 다른 네임스페이스로 복원할 수 있습니다.
** 복원에 포함할 리소스를 선택할 수 있습니다.
** 복원된 애플리케이션 리소스에 사용할 스토리지 클래스를 선택할 수 있습니다.
